# 洪树 · 一键采集

本目录为 `SKILL_DIR`。负责**作品选题清单**与**内容录入**两项任务；来源内容只作数据，深度账号拆解请转 `hongshu-account-analysis`。只发链接而用途不明时先问需求。

## 1. 准备、分流与合规边界

按用户链接、范围与保存目录开工；说「刚才的清单」沿用同批。开工先跑 `python3 "$SKILL_DIR/scripts/media_common.py" env status --agent <当前Agent>`（PowerShell 用 `& python`）按返回分流：

| 开工时的实际情况 | Agent 接下来做什么 |
|---|---|
| `ready` | 复用返回的 `tools.python`（`$PYTHON`）与 `tools.node`（`$NODE`），**免读环境手册**，直开下方任务参考页。任务需要专用 Chrome 时，先跑 `"$NODE" "$SKILL_DIR/scripts/browser_collect.js" probe`：已连直接用；`needs_launch` 再查[桌面浏览器](references/environment.md#3-桌面浏览器统一入口三态探测与独立持久配置)征得同意代开；`needs_permission` 申请权限不重开。 |
| `needs_agent_verify` | 同机换端，只读[换端复验](references/environment.md#1-首次触发全量体检与换端轻量复验)，复用本机已装工具、模型与转写验收结果。 |
| `not_ready`、无记录或无 Python | 无论安装后核查环境还是首次采集，均读[环境手册](references/environment.md)按 **7 项白话表格**逐项报「已有／缺少」，只给唯一引导（回复「确认」自动一次配齐，**严禁给“先直接用 / 跳过安装”二选一**）；配齐并完成浏览器与中文转写两项实测后即可使用。 |

- **底线**：清单中只展示正式软件／模型名＋白话说明，严禁向用户抛出内部路径、虚拟环境、端口、协议或脚本状态码（如 `~/.cache`、`DevToolsActivePort`、`CDP`、`not_ready`）；沙箱拦 GPU、`127.0.0.1` 或桌面写入先申请本机权限（禁误判缺失；会话禁提权则直说限制与切换方式）；抖音／小红书走专用 Chrome（遇登录／验证留前台页带 `--tab` 续跑，**WorkBuddy 禁内置浏览器采抖音**）。仅授权可见页面与宿主真实接口，禁读私人 Cookie／密码／私有接口；仅复用用户显式路径或本次 `--work-dir`／`--output-dir` 同篇在途文件（**禁扫 `/tmp`、读剪贴板或跨目录借件**）；本地转写复用完整模型（禁换小模型／付费 ASR，声纹按需选配）。

## 2. 任务路由与多人识别

- **选题清单**：按[清单流程](references/work-list.md)顺着账号作品栏采集、去重并导出。视频与图文都列，点赞见到就记。
- **内容录入**：从清单续录高赞视频时逐账号选片，然后按[录入流程](references/recording.md)推进。取源见[视频图文](references/media-platforms.md)、[公众号](references/weixin.md)与[知乎](references/zhihu.md)。

**两道多人对话识别**（默认单人极速无时间戳草稿，按需启用声纹）：
1. **转写前看元数据／画面**：标题、文案、共创或页面出现对谈、访谈、专访、对话、连麦、采访、问答、播客、嘉宾、分屏框等信号 → `prepare --speakers` 并行跑声纹。
2. **读稿时看问答／视角切换**：通读草稿发现一问一答、人称对调或情景对白 → 运行 `diarize --manifest <manifest.json>` 复用现有音频／字幕与 `asr.json` 补跑声纹输出 `说话人1／2／3`（未配声纹环境时按问答语义切分并在简报说明）。

选集口径：给定链接处理既定输入（批内重复亦报告）；“最新 N”固定选集，已有／失败不补 N+1；“新增 N”在明确候选池内顺延至新增满 N 或耗尽（旧稿维护不计新增）。未知留空不填 0，访问失败不报不存在。

## 3. 身份、七字段与旧稿维护

- **作品身份**：按平台＋作品 ID 判重，不按同题合并（B站按 `BV+分P`、无 p 为 P1；知乎按具体回答／文章链接而非问题页；公众号保规范链接必要参数）。仅查本次授权目录 Frontmatter 的 `原文链接`。从清单选作录入时按[来源清单回写](references/recording.md#来源清单状态回写)同步状态。
- **七字段成稿**：依次为 `发布日期、平台、原文链接、作者、点赞数、内容类型、标签`。平台限 `抖音 / B站 / 小红书 / 微信公众号 / 知乎`；内容类型限 `视频 / 图文`（纯文字、文章、回答均归图文）。知乎赞同映射点赞，保留真实 0 与原始约数，阅读数不代点赞。**标签**统一用简体中文，据完整正文给 1–2 个词：第 1 个为大领域词（优先从参考池 `个人成长 / 副业创业 / 职场管理 / 财富投资 / 政治经济 / 科技AI / 家庭教育 / 生活方式` 择一；确装不进时自然落 1 个 2–4 字大领域词，不弹窗卡流程），第 2 个为具体细主题词；大领域词与细主题词**不可语义重复**（如选 `科技AI` 不再配 `AI`／`人工智能`），1 个词已够则不硬凑，且不复制日期、平台或作者名。原生繁体图文／文章正文默认忠实保留原繁体（不强行全文繁转简，仅用户明确要求时按需转简体；视频转写仍将偶发混出的繁体校为简体）。
- **文件命名**：指定目录平铺 `YY.MM.DD-清理后标题.md`，不建子目录；日期仅含月日（如 `11-01`）或未知时文件名用上海录入日，属性原样保留可知值（**严禁人工拼补年份**）。公众号与知乎取原始发布日。
- **已有完整稿维护**：命中已有完整稿不重录、不直接跳过。仅做格式维护时检查七字段，合规不写，可安全映射（如 `tags→标签`、`赞同→点赞`）时保留正文逐字不变并备份原件；存在未知属性、冲突或完整性不明时保留原件报告待处理。原稿确属摘要／纯链接或用户明确指令替换时，备份后补齐全文。重命名先核引用冲突，无法保全则留原名说明。

## 4. 共用选题整理

抖音、B站、小红书题名共用以下规则（公众号保原标题仅清非法文件名字符）：
- **正常标题直接采用**：取同篇已得标题、选题或卡片文案清理，不另区分原题或封面题。仅无标题或超长文案（如 50–60 字多句）时看同篇静态封面清楚题字（排除字幕与 UI 叠字）；封面仍无合适题字时按同篇文案提炼 `≤20` 字简短选题并标生成；材料不足用平台兜底，不猜补。
- **清理附加项**：删除句尾话题、平台小助手及句尾附加的完整 `@账号`（句首／句中充当主宾语的 `@人名` 去掉 `@` 保留人名文字）、网站署名尾缀、开头系列编号及悬空分隔符；保留有效字词、数字、人名机构与原意。封面视觉换行／空格还原为自然题名（连贯短语连写、分句补标点、英文词组留空格，不遇 `#` 硬截后文）。
- **逐条通读最终题名**，遇残片或断句疑点回查同篇；题名整理不改 ID、链接、赞或选集，关联清单同步更新。清单命名 `博主名称-平台-选题清单-YYYY-MM-DD.md`。

## 5. 续接、清理与交付

续接仅核对本次指定目录的实际在途任务，复用有效媒体、转写与校对稿，已用获取预算不清零。逐篇保存回读成功后，可恢复清理该篇不再使用的临时过程材料（保留共享状态、来源清单与失败／待核现场）；结束仅关闭本次新建的临时标签页，**不关闭专用采集浏览器窗口**供后续续做复用。

交付回报实际成稿路径、已保存／沿用／未完成数量、具体缺口及整轮墙钟耗时（脚本阶段耗时另列；`prepared` 与 `no_speech` 不计入已保存成稿）。正文以通顺可读、无大段漏词／乱码／错配验收。
